# تیکت‌یار — سیستم مدیریت تیکت پشتیبانی

[English](README.md) | فارسی

تیکت‌یار یک پلتفرم فول‌استک فارسی و راست‌به‌چپ برای تیم‌های پشتیبانی است که به گردش‌کار شفاف و قابل حسابرسی نیاز دارند. کاربران تیکت می‌سازند، گفتگو را دنبال می‌کنند و در صورت مجاز بودن، تیکت حل‌شده را دوباره باز می‌کنند. تیم پشتیبانی صف مشترک را بررسی می‌کند، مسئول تعیین می‌کند، وضعیت و اولویت را تغییر می‌دهد و یادداشت‌های داخلی را از دید کاربر پنهان نگه می‌دارد. حساب مالک، مدیران، نشست‌ها و رویدادهای امنیتی را مدیریت می‌کند.

رابط کاربری به‌صورت پیش‌فرض فارسی و راست‌به‌چپ است؛ ایمیل، سکرت و شناسه تیکت چپ‌به‌راست نمایش داده می‌شوند.

## امکانات

- ثبت‌نام، ورود، تأیید ایمیل، بازیابی رمز و مدیریت نشست
- نقش‌های `USER`، `ADMIN` و `OWNER` با ماتریس مجوز مرکزی و پیش‌فرض «رد دسترسی»
- ورود مدیران فقط با کلید امنیتی؛ مدیر و مالک در اولین ورود نام و ایمیل خود را تکمیل می‌کنند
- نشست سمت سرور با عمر یک ساعت، چرخش توکن و ابطال در رویدادهای امنیتی
- ورود دومرحله‌ای اختیاری با TOTP و کدهای بازیابی یک‌بارمصرف
- تیکت با دسته‌بندی، اولویت، شناسه عمومی (`TK-00001`)، جستجو، فیلتر، مرتب‌سازی و صفحه‌بندی
- پاسخ عمومی، یادداشت داخلی مخصوص کارکنان و تایم‌لاین کامل فعالیت
- گردش وضعیت: `OPEN`، `IN_PROGRESS`، `WAITING_FOR_USER`، `RESOLVED`، `CLOSED`
- داشبورد و صف تیکت واقعی برای کارکنان، به‌همراه مدیریت نقش، حسابرسی و نشست برای مالک
- به‌روزرسانی‌های احراز هویت‌شده Socket.IO با مجوز اتاق هر تیکت و دریافت مجدد پس از اتصال
- تم روشن/تاریک، چیدمان واکنش‌گرا، حالت‌های skeleton/خالی/خطا و کامپوننت‌های دسترس‌پذیر

## پشته فناوری

| بخش        | انتخاب                                                       |
| ---------- | ------------------------------------------------------------ |
| فریم‌ورک   | Nuxt 4 (Vue 3، Nitro، Vite)                                  |
| زبان       | TypeScript (strict)                                          |
| استایل     | Tailwind CSS 4 و کامپوننت‌های shadcn-vue-style روی `reka-ui` |
| دیتابیس    | SQLite + Prisma 7 (`@prisma/adapter-better-sqlite3`)         |
| اعتبارسنجی | Zod 4 در همه مرزهای اعتماد                                   |
| احراز هویت | نشست سمت سرور، Argon2id، کلید امنیتی کارکنان، TOTP           |
| Realtime   | Socket.IO 4                                                  |
| ایمیل      | Nodemailer (SMTP اختیاری)                                    |
| تست        | Vitest (واحد/یکپارچه) و Playwright (E2E)                     |

پروژه از `npm` و `package-lock.json` استفاده می‌کند. برای نصب تکرارپذیر `npm ci` را اجرا کنید.

## پیش‌نیازها

- Node.js 20.19+ یا 22.12+
- npm 10+
- Chrome/Chromium برای تست‌های E2E

## شروع سریع

```bash
npm ci
cp .env.example .env
```

دو کلید ۳۲ بایتی لازم را بسازید و در `.env` قرار دهید:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

سپس مهاجرت‌ها را اعمال و سرور توسعه را اجرا کنید:

```bash
npm run db:deploy
npm run dev
```

آدرس: <http://localhost:3000>

### راه‌اندازی مالک

`OWNER_SECRET` را روی یک مقدار تصادفی حداقل ۳۲ کاراکتری تنظیم کنید. هنگام اجرا، اگر حساب `OWNER` وجود نداشته باشد، تیکت‌یار آن را می‌سازد. با همان سکرت در `/admin/login` وارد شوید و نام و ایمیل خود را تکمیل کنید. تغییر `OWNER_SECRET` کلید مالک را به‌روزرسانی و نشست‌های قبلی مالک را باطل می‌کند.

مدیران از صفحه کاربران ساخته می‌شوند. هر مدیر یک کلید یک‌بارمصرف از سرور دریافت می‌کند و فقط hash جستجوی SHA-256 آن ذخیره می‌شود. مسیر CLI اختیاری: `npm run bootstrap:owner`.

## متغیرهای محیطی

| متغیر                | الزامی               | توضیح                                                                                |
| -------------------- | -------------------- | ------------------------------------------------------------------------------------ |
| `NODE_ENV`           | بله                  | `development` یا `production`                                                        |
| `APP_URL`            | بله                  | آدرس عمومی مطلق برای CSRF، canonical URL و لینک ایمیل‌ها                             |
| `DATABASE_URL`       | بله                  | مسیر فایل SQLite، مثلاً `file:./data/app.db`                                         |
| `MFA_ENCRYPTION_KEY` | بله                  | کلید ۳۲ بایتی Base64 برای رمزنگاری TOTP با AES-256-GCM                               |
| `IP_HASH_SECRET`     | بله                  | کلید ۳۲ بایتی Base64 برای pseudonymize کردن IP                                       |
| `OWNER_SECRET`       | برای راه‌اندازی مالک | سکرت سمت سرور با حداقل ۳۲ کاراکتر                                                    |
| `SMTP_*`             | اختیاری              | `SMTP_HOST`، `SMTP_PORT`، `SMTP_USER`، `SMTP_PASSWORD`، `SMTP_FROM` برای ارسال ایمیل |
| `TRUST_PROXY`        | اختیاری              | فقط پشت reverse proxy مورد اعتماد `true` شود                                         |
| `ALLOW_SEED`         | اختیاری              | برای اجرای seed توسعه باید `true` باشد                                               |

`.env` در Git نادیده گرفته می‌شود و `.env.example` فقط placeholder دارد. بدون SMTP، ارسال هرگز موفق گزارش نمی‌شود. در توسعه پیام‌ها در پوشه gitignored `.data/mail-outbox/` ذخیره می‌شوند تا لینک تأیید و بازیابی بدون ثبت توکن در log قابل استفاده باشد. در production پیام ارسال‌نشده فقط با هشدار drop می‌شود.

## دیتابیس و مهاجرت‌ها

```bash
npm run db:generate   # ساخت Prisma Client
npm run db:migrate    # ساخت/اعمال مهاجرت توسعه
npm run db:deploy     # اعمال مهاجرت‌های commit‌شده
npm run db:seed       # داده نمونه (نیازمند ALLOW_SEED=true)
```

تنها مسیر رسمی مهاجرت Prisma Migrate است؛ در production از `prisma db push` استفاده نکنید. seed در production، بدون `ALLOW_SEED=true` یا روی دیتابیس غیرخالی اجرا نمی‌شود و اعتبارنامه‌ها را تصادفی می‌سازد.

فایل دیتابیس و بکاپ‌ها در `data/` قرار می‌گیرند و در Git نیستند. SQLite به فضای ذخیره‌سازی محلی و پایدار نیاز دارد؛ از فایل‌سیستم موقت یا شبکه استفاده نکنید.

## اسکریپت‌ها

| دستور                                    | کاربرد                            |
| ---------------------------------------- | --------------------------------- |
| `npm run dev`                            | اجرای سرور توسعه                  |
| `npm run build`                          | ساخت Prisma Client و build تولید  |
| `npm run preview`                        | پیش‌نمایش build تولید             |
| `npm run typecheck`                      | بررسی نوع Nuxt/Vue/TypeScript     |
| `npm run lint`                           | اجرای ESLint                      |
| `npm test`                               | تست‌های واحد و یکپارچه            |
| `npm run test:unit` / `test:integration` | اجرای یک لایه تست                 |

| `npm run bootstrap:owner`                | راه‌اندازی مالک از `OWNER_SECRET` |

Vitest از دیتابیس جداگانه `data/test.db` استفاده می‌کند و قبل از هر اجرا مهاجرت‌ها را replay می‌کند. Playwright سرور توسعه را روی پورت `3000` اجرا یا استفاده مجدد می‌کند.

## Build و Preview لوکال

```bash
npm run db:deploy   # اعمال مهاجرت‌ها روی data/app.db
npm run build       # prisma generate + nuxt build
npm run preview     # اجرای build روی http://localhost:3000
```

مسیر نسبی `DATABASE_URL` از ریشه پروژه resolve می‌شود، حتی وقتی `nuxt preview` داخل `.output` اجرا می‌شود؛ بنابراین preview از همان `data/app.db` توسعه و Prisma CLI استفاده می‌کند. اگر preview خطای نبود جدول داد، `npm run db:deploy` را با همان `DATABASE_URL` اجرا کنید.

preview با `NODE_ENV=production` اجرا می‌شود، اما وقتی `APP_URL` یک آدرس loopback باشد پرچم `Secure` کوکی غیرفعال می‌شود تا ورود روی HTTP ساده کار کند. از `http://localhost:3000` یا `http://127.0.0.1:3000` استفاده کنید؛ originهای واقعی production پرچم `Secure` را حفظ می‌کنند.

## تست و کیفیت

```bash
npm run lint
npm run typecheck
npm test
npm run test:e2e
```

تست‌ها مرزهای مجوز (شامل دسترسی بین‌کاربری به تیکت)، ارتقای نقش، ابطال نشست، MFA، جریان‌های CSRF، گذارهای تیکت، پاک‌سازی audit، اعتبارسنجی redirect و escape ایمیل را پوشش می‌دهند.

## امنیت

- رمز عبور با Argon2id هش می‌شود؛ رمز ساده هرگز ذخیره یا log نمی‌شود.
- توکن نشست تصادفی است، فقط به‌صورت SHA-256 ذخیره می‌شود، در کوکی `HttpOnly` ارسال می‌شود و برای originهای غیرلوکال production پرچم `Secure` دارد.
- درخواست‌های تغییردهنده نیازمند CSRF double-submit و `Origin` مورد اعتماد هستند.
- هر تیکت، پیام، نشست و اقدام مدیریتی مجوز سطح شیء و نقش را در سرور بررسی می‌کند.
- ورود، ثبت‌نام، بازیابی رمز، نوشتن تیکت و رویدادهای Socket.IO محدودیت نرخ دارند.
- سکرت TOTP در حالت سکون رمزنگاری می‌شود؛ کدهای بازیابی یک‌بارمصرف و هش‌شده‌اند.
- رکوردهای audit سکرت‌ها را پاک‌سازی و IP را هش‌شده ذخیره می‌کنند.
- CSP، HSTS (production)، `X-Frame-Options`، `nosniff`، `Referrer-Policy`، CORP و permissions policy اعمال می‌شوند.

هیچ سیستمی کاملاً امن نیست. از TLS، سکرت‌های قوی، وابستگی‌های به‌روز، بکاپ پایدار و دسترسی عملیاتی بازبینی‌شده استفاده کنید. مدل تهدید و محدودیت‌ها در [docs/SECURITY.md](docs/SECURITY.md) آمده است.

## ساختار پروژه

```text
app/                 صفحات، layoutها، کامپوننت‌ها، composableها و گارد مسیر
server/api/          هندلرهای HTTP نیترو
server/services/     قواعد کسب‌وکار و مجوزها
server/middleware/   هدرهای امنیتی، صدور CSRF و محدودیت API
server/plugins/      اعتبارسنجی env، راه‌اندازی مالک و Socket.IO
server/utils/        نشست، رمزنگاری، MFA، audit، ایمیل و realtime
prisma/              اسکیما، مهاجرت‌ها، seed و کلاینت تولیدشده
shared/              واژگان دامنه، مجوزها، اسکیمای Zod و DTOهای API
scripts/             CLI راه‌اندازی مالک
tests/               تست‌های واحد، یکپارچه و E2E
docs/                معماری، امنیت و استقرار
```

کامپوننت‌های Vue هرگز Prisma یا ماژول‌های سمت سرور را import نمی‌کنند؛ دسترسی دیتابیس فقط در serviceها و utilityهای سرور است.

## استقرار

راه‌اندازی production، TLS/reverse proxy، ذخیره‌سازی پایدار SQLite، بکاپ، restore، مهاجرت و rollback در [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) مستند شده است. استقرار production تأییدشده‌ای در این مخزن وجود ندارد؛ قبل از رفتن به live چک‌لیست عملیاتی را بررسی کنید.

## محدودیت‌های شناخته‌شده

- پیوست فایل عمداً پیاده‌سازی نشده است.
- محدودیت نرخ و وضعیت Socket.IO در حافظه است؛ استقرار چندنمونه‌ای به shared store و Socket.IO adapter نیاز دارد.
- SQLite برای هم‌زمانی نوشتن بالا طراحی نشده است.
- تأیید ایمیل وجود دارد اما برای ورود الزامی نیست.
- CSP هنوز inline script را مجاز می‌کند چون Nuxt با payload inline hydrate می‌شود؛ CSP مبتنی بر nonce کار آینده است.

## عیب‌یابی

- **`Missing required environment variable`** — `.env.example` را به `.env` کپی و همه کلیدهای الزامی را تنظیم کنید.
- **`table main.User does not exist`** — دیتابیس اسکیما ندارد. `npm run db:deploy` را با همان `DATABASE_URL` اجرا و preview را دوباره شروع کنید.
- **ورود به بخش مدیران ممکن نیست** — کارکنان با کلید امنیتی در `/admin/login` وارد می‌شوند، نه ایمیل/رمز. اگر کلید مالک گم شد، `OWNER_SECRET` را عوض کنید؛ مالک به کلید جدید متصل و نشست‌های قبلی باطل می‌شوند.
- **ورود بعد از بازیابی رمز ناموفق است** — نشست‌های قبلی طبق طراحی باطل شده‌اند؛ دوباره وارد شوید.
- **ایمیل تأیید نمی‌رسد** — SMTP را تنظیم کنید؛ در توسعه `.data/mail-outbox/` را ببینید.
- **`database is locked`** — SQLite فقط یک نویسنده هم‌زمان می‌پذیرد؛ نوشتن هم‌زمان سنگین و فایل‌سیستم شبکه را کنار بگذارید.
- **تست‌های E2E روی پورت 3000 شکست می‌خورند** — فرایند مزاحم را متوقف کنید یا اجازه دهید Playwright خودش سرور را اجرا کند.
